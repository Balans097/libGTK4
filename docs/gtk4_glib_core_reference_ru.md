# GTK4 (GLib core utilities: memory / strings / timers / main loop) — справочник модуля

> **Импорт:** `import libGTK4`
> **Область применения:** низкоуровневые утилиты GLib, на которые то и дело приходится опираться при написании обработчиков и вспомогательного кода в остальных справочниках этой серии — управление памятью C-строк, отложенные и периодические вызовы, ручной доступ к главному циклу событий. Тринадцатая часть серии справочников по обёртке; предполагает знакомство с `gtk4_core_reference_ru.md` (`GtkApplication`, `g_application_run`).

Этот справочник компактнее остальных — все функции здесь скорее "инструменты на каждый день", встречавшиеся мимоходом уже в предыдущих справочниках (например, `g_timeout_add` упоминался в примерах пульсирующего индикатора прогресса), чем отдельная тематическая область GTK.

## Память и строки: `g_free`, `g_malloc`, `g_strdup` и родственные

Функции этого раздела работают с памятью, выделенной **на стороне C** через аллокатор GLib, — то есть с памятью, полученной от других функций этой обёртки, возвращающих `cstring`/`pointer`, выделенные самой GTK/GLib (а не Nim-строками/объектами, за которые отвечает сборщик мусора Nim). Смешивать эти два мира без понимания того, что чем управляется, — частый источник ошибок в FFI-коде.

### `g_free`

```nim
proc g_free*(mem: gpointer)
```

**Что делает.** Освобождает память, выделенную функциями GLib/GTK (`g_malloc`, `g_strdup`, и множеством других функций этой обёртки, чья документация в комментариях к заголовкам GTK явно указывает на необходимость освобождения возвращаемого значения вызывающим кодом). Вызов `g_free` на памяти, не выделенной через аллокатор GLib (например, на обычной Nim-строке, преобразованной в `cstring` через `$`/`.cstring`), — неопределённое поведение.

- **Реализация.** Большинство `get_*`-функций в этой серии справочников, возвращающих `cstring`, возвращают указатель на память, которой владеет сам GTK-объект (например, `gtk_window_get_title`) — такую строку **не нужно** освобождать вручную, GTK делает это сама при изменении/уничтожении объекта. Освобождать вручную через `g_free` нужно только значения, явно документированные как "владение переходит вызывающему коду" (например, результат `g_strdup_printf` ниже) — в общем случае для функций этой обёртки такое разделение не отражено в сигнатурах типов (оба случая выглядят как обычный `cstring`), и его нужно сверять с документацией конкретной функции GTK.

- `mem` — указатель на память, выделенную GLib.

```nim
let duplicated = g_strdup("временная строка")
echo "Скопированная C-строка используется здесь"
g_free(cast[gpointer](duplicated))
echo "Память корректно освобождена"
```

### `g_malloc` / `g_malloc0`

```nim
proc g_malloc*(nBytes: gsize): gpointer
proc g_malloc0*(nBytes: gsize): gpointer
```

**Что делает.** Выделяют блок памяти заданного размера через аллокатор GLib — нужны в первую очередь при подготовке буферов для передачи в C-функции, ожидающие, что вызывающий код сам выделил память нужного размера (а не приняли готовое значение). `g_malloc0` дополнительно обнуляет выделенную память (аналог `calloc` в чистом C) — безопаснее для структур, где непроинициализированные поля могут привести к неопределённому поведению при последующем использовании; `g_malloc` быстрее, но оставляет содержимое памяти неопределённым.

- `nBytes` — размер выделяемого блока в байтах.

```nim
let buffer = g_malloc0(256)
echo "Обнулённый буфер в 256 байт выделен через аллокатор GLib"
# ... использование buffer в C-совместимом API ...
g_free(buffer)
```

### `g_strdup`

```nim
proc g_strdup*(str: cstring): cstring
```

**Что делает.** Создаёт копию C-строки, выделенную через аллокатор GLib, — нужен, когда C-функция, в которую нужно передать строку, сохраняет переданный указатель для последующего использования (а не копирует содержимое сама внутри себя), а исходная Nim-строка, из которой была получена `cstring`, может быть впоследствии освобождена сборщиком мусора Nim, что сделает такой сохранённый указатель "болтающимся". Результат `g_strdup` нужно в итоге освободить через `g_free`, когда он больше не нужен.

- `str` — исходная строка для копирования.

```nim
let safeCopy = g_strdup("значение, которое сохранится в C-структуре надолго")
echo "Независимая C-копия строки создана"
```

---

### `g_strdup_printf`

```nim
proc g_strdup_printf*(format: cstring): cstring {.varargs.}
```

**Что делает.** Формирует новую строку по `printf`-подобному шаблону (та же логика форматирования, что у `gtk_message_dialog_new` из справочника по window chrome — `%s` для строк, `%d` для чисел и т.д.), выделяя результат через аллокатор GLib. В отличие от Nim-строковой интерполяции (`&`, `fmt`), результат — `cstring`, которую в итоге нужно освободить через `g_free`.

- **Реализация.** Как и у `gtk_message_dialog_new`, при формировании строки из непроверенных пользовательских данных стоит избегать подстановки самого пользовательского ввода в качестве шаблона формата — только как аргумента к готовому `%s` в шаблоне, заданном самим приложением.

- `format` — `printf`-подобная строка формата, с последующими аргументами по необходимости.

```nim
let message = g_strdup_printf("Обработано %d из %d файлов", 3, 10)
echo $message
g_free(cast[gpointer](message))
```

### `g_strcmp0`

```nim
proc g_strcmp0*(str1: cstring, str2: cstring): gint
```

**Что делает.** Сравнивает две C-строки, безопасно обрабатывая `nil` в качестве любого из аргументов (обычный `strcmp` из чистого C при `nil`-аргументе приводит к неопределённому поведению/аварийному завершению) — `nil` считается "меньше" любой не-`nil` строки, два `nil` считаются равными. Возвращает отрицательное число, `0` или положительное — та же семантика, что у стандартного `strcmp`. Полезен при работе с результатами функций этой обёртки, которые могут вернуть `nil` (например, `gtk_button_get_icon_name`, если содержимое кнопки не было установлено как иконка), когда нужно сравнить такой результат со строкой без предварительной ручной проверки на `isNil`.

- `str1`, `str2` — сравниваемые строки, любая может быть `nil`.

```nim
let iconName = gtk_button_get_icon_name(someButton)  # может вернуть nil
if g_strcmp0(iconName, "document-save-symbolic") == 0:
  echo "Это кнопка сохранения"
# сравнение безопасно, даже если iconName оказался nil
```

## Отложенные и периодические вызовы

GTK не предоставляет отдельного API для таймеров — периодические и отложенные вызовы идут через общий механизм главного цикла событий GLib (`GMainLoop`, тот же, что приводит в движение весь `g_application_run` из справочника по core-разделу). Функция обратного вызова для всех процедур этого раздела имеет единую сигнатуру `GSourceFunc`: `proc(userData: gpointer): gboolean {.cdecl.}` — возвращаемое значение определяет, должен ли вызов повториться (`1.gboolean`) или это был последний вызов (`0.gboolean`).

### `g_timeout_add` / `g_timeout_add_seconds`

```nim
proc g_timeout_add*(interval: guint, function: GSourceFunc, data: gpointer): guint
proc g_timeout_add_seconds*(interval: guint, function: GSourceFunc, data: gpointer): guint
```

**Что делает.** Регистрируют функцию, вызываемую периодически (пока сама функция возвращает `1.gboolean`) через равные промежутки времени. `g_timeout_add` задаёт интервал в миллисекундах — точнее, но чуть более затратно для системы при очень частых пробуждениях. `g_timeout_add_seconds` — интервал в секундах, с округлением момента срабатывания GLib самостоятельно "выравнивает" по ближайшим удобным системным меткам для экономии энергии — предпочтительнее для не критичных ко времени периодических действий (например, ежеминутное обновление часов на экране, а не раз в 60000 миллисекунд с точностью до миллисекунды). Обе возвращают идентификатор `guint`, который можно передать в `g_source_remove` для досрочной отмены.

- `interval` — период в миллисекундах (для `add`) или секундах (для `add_seconds`).
- `function` — функция обратного вызова (`GSourceFunc`).
- `data` — пользовательские данные, передаваемые в `function`.

```nim
proc onTick(userData: gpointer): gboolean {.cdecl.} =
  echo "Тик таймера"
  result = 1.gboolean  # 1 — продолжать вызывать; 0 — остановить после этого вызова

let timerId = g_timeout_add(1000, onTick, nil)
echo "Таймер с интервалом в 1 секунду запущен, id=", timerId
```

---

### `g_idle_add`

```nim
proc g_idle_add*(function: GSourceFunc, data: gpointer): guint
```

**Что делает.** Регистрирует функцию, вызываемую при первой же возможности, когда главный цикл событий свободен от более приоритетных задач (перерисовки экрана, обработки пользовательского ввода), — не по расписанию, а "как только появится момент простоя". Полезно для разбиения тяжёлой, но быстрой построчной обработки на мелкие шаги, чтобы не блокировать интерфейс одним долгим синхронным вызовом (см. раздел IV, «Перенос тяжёлой, но быстрой обработки»), и для отложенных действий, которые не критичны по конкретному времени, а важны лишь "чуть позже, не прямо сейчас в этом кадре".

- `function` — функция обратного вызова (`GSourceFunc`), та же сигнатура, что у `g_timeout_add`.
- `data` — пользовательские данные.

```nim
proc processNextChunk(userData: gpointer): gboolean {.cdecl.} =
  echo "Обработана очередная порция данных"
  # result = 1.gboolean, если есть ещё данные для обработки; 0.gboolean, если обработка завершена
  result = 0.gboolean

discard g_idle_add(processNextChunk, nil)
echo "Обработка запланирована на первый простой главного цикла"
```

---

### `g_source_remove`

```nim
proc g_source_remove*(tag: guint): gboolean
```

**Что делает.** Досрочно отменяет ранее зарегистрированный таймер или idle-обработчик по его идентификатору (возвращённому от `g_timeout_add`/`g_timeout_add_seconds`/`g_idle_add`) — нужен, когда условие для дальнейших срабатываний перестало быть актуальным раньше, чем сам обработчик успел бы вернуть `0.gboolean` естественным образом (например, окно, для которого шёл периодический опрос состояния, было закрыто пользователем).

- `tag` — идентификатор таймера/idle-обработчика.

```nim
g_source_remove(timerId)
echo "Таймер отменён досрочно"
```

## Главный цикл: `g_main_loop_new` и родственные

`GMainLoop` — низкоуровневый объект главного цикла событий, тот же механизм, что скрыт внутри `g_application_run` из справочника по core-разделу. Прямое создание и запуск `GMainLoop` вручную нужны редко — почти всегда достаточно `GtkApplication`/`g_application_run`; явное использование уместно для консольных утилит или служебных процессов, использующих асинхронные операции GLib (таймеры, чтение из потоков), но не показывающих никакого GTK-интерфейса вовсе.

### `g_main_loop_new` / `g_main_loop_run` / `g_main_loop_quit`

```nim
proc g_main_loop_new*(context: pointer, isRunning: gboolean): pointer
proc g_main_loop_run*(loop: pointer)
proc g_main_loop_quit*(loop: pointer)
```

**Что делает.** `g_main_loop_new` создаёт объект главного цикла — `context` почти всегда передаётся как `nil` (использовать контекст по умолчанию), `isRunning` — устаревший параметр, обычно `0.gboolean`. `g_main_loop_run` запускает цикл и блокирует выполнение (аналогично `g_application_run`), пока не будет вызван `g_main_loop_quit` — из обработчика таймера/idle/сигнала, поскольку сам `run` блокирует поток, вызвавший его.

- `context` — контекст главного цикла, обычно `nil`.
- `isRunning` — устаревший параметр, обычно `0.gboolean`.
- `loop` — объект главного цикла.

```nim
let loop = g_main_loop_new(nil, 0.gboolean)

proc onDone(userData: gpointer): gboolean {.cdecl.} =
  echo "Фоновая задача завершена, останавливаем цикл"
  g_main_loop_quit(cast[pointer](userData))
  result = 0.gboolean

discard g_timeout_add(5000, onDone, loop)
g_main_loop_run(loop)  # блокирует выполнение на 5 секунд, затем завершается
echo "Главный цикл завершён"
```

## Практические рецепты

### Периодическое обновление часов в интерфейсе

Надпись с текущим временем, обновляемая раз в секунду.

```nim
import times

proc onClockTick(userData: gpointer): gboolean {.cdecl.} =
  let clockLabel = cast[GtkLabel](userData)
  gtk_label_set_text(clockLabel, now().format("HH:mm:ss").cstring)
  result = 1.gboolean

proc startClock(clockLabel: GtkLabel): guint =
  result = g_timeout_add(1000, onClockTick, cast[gpointer](clockLabel))
  echo "Часы запущены, обновление раз в секунду"

let clockLabel = gtk_label_new("")
let clockTimerId = startClock(clockLabel)
# g_source_remove(clockTimerId) — при закрытии окна, если часы больше не нужны
```

### Однократная отложенная операция

Показ подсказки через 2 секунды после запуска приложения, без периодического повторения.

```nim
proc showDelayedHint(userData: gpointer): gboolean {.cdecl.} =
  echo "Показываем подсказку через 2 секунды после старта"
  result = 0.gboolean

discard g_timeout_add(2000, showDelayedHint, nil)
```

### Перенос тяжёлой, но быстрой обработки на "простой" цикл через idle

Обработка большого списка элементов маленькими порциями, чтобы не блокировать интерфейс одним долгим синхронным вызовом.

```nim
var itemsToProcess: seq[string] = @["item1", "item2", "item3", "item4", "item5"]
var processedCount = 0

proc processOneItem(userData: gpointer): gboolean {.cdecl.} =
  if processedCount < itemsToProcess.len:
    echo "Обработан элемент: ", itemsToProcess[processedCount]
    processedCount += 1
    result = 1.gboolean
  else:
    echo "Обработка всех элементов завершена"
    result = 0.gboolean

discard g_idle_add(processOneItem, nil)
echo "Обработка списка запущена порциями по одному элементу за простой цикла"
```

### Безопасное сравнение строк, одна или обе из которых могут быть nil

Типичный паттерн при работе с результатами `get_*`-функций GTK, которые могут вернуть `nil`.

```nim
proc isSaveIcon(button: GtkButton): bool =
  let iconName = gtk_button_get_icon_name(button)
  result = g_strcmp0(iconName, "document-save-symbolic") == 0

echo "Это кнопка сохранения: ", isSaveIcon(someButton)
```

## Сводка: какую процедуру выбрать

- **Регулярное действие с чётким интервалом времени** → `g_timeout_add`/`g_timeout_add_seconds` — секундный вариант предпочтительнее для неточных по времени периодических действий.
- **Действие нужно выполнить "как можно скорее, но не блокируя интерфейс прямо сейчас"** → `g_idle_add`, а не `g_timeout_add` с интервалом `0`.
- **Таймер/idle-обработчик может понадобиться отменить раньше времени** → сохранить идентификатор и вызвать `g_source_remove`.
- **Строка от функции GTK, которая может вернуть `nil`, сравнивается с другой строкой** → `g_strcmp0`, а не обычное Nim-сравнение, которое упадёт при `nil`.
- **C-строка/буфер должны пережить исходную Nim-строку** → `g_strdup`/`g_malloc` с обязательным `g_free` впоследствии.
- **Консольная утилита без GTK-интерфейса** → `g_main_loop_new`/`run`/`quit` напрямую. **Есть хотя бы одно окно GTK** → `GtkApplication`/`g_application_run` — отдельно создавать `GMainLoop` не нужно.
